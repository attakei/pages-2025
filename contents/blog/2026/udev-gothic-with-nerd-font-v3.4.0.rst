UDEV Gothicをフォークして、Nerd Font v3.4.0に対応してみた
=========================================================

.. post:: 2026-04-18
   :category: Tech
   :tags: Font,Claude,GenerativeAI

自分はCLI/TUIの環境向けにずっと `HackGen Console NF <https://github.com/yuru7/HackGen>`_ を使っていた。
で、最近になってNeoVimなどでYAMLのアイコンに使われている "" [#]_ が表示されてないことに意識がいくようになった。

.. [#] Unicodeでは ``E8EB`` にあたる。対応しているフォントを使っていると、``YAML`` が四方に配置された文字が表示される。

Nerd Fontではv3.4.0で有効になっているのだが、HackGen NFはv3.3.0をもとにビルドしている。
そのため、このままだと表示することができない。
さらに、アップデートされるとも限らない。 [#]_

.. [#] いわゆるOSSと同等の枠での取り組みであろうことは想像できるため、こればっかりはしょうがない。

そこで、まずは自分の環境で「Nerd Fornt v3.4.0に対応したHackGen」を作ってみようかと考えてみた。
ソースまわりはビルド用のスクリプトごとGitHubで公開されているため、取り組みやすそうではあるのだが、
ビルド環境についての説明に若干及び腰になる記述 [#]_ があったので、ひとまず別の方法を模索することに。

.. [#] Python 2.x 系を必要としてるっぽい点や、sudoを必要としていた点あたり。

いろいろあった結果、「Nerd Font v3.4.0に対応したUDEV Gothicを自前ビルドする」という方針で動くことになった。

https://github.com/attakei-lab/udev-gothic/tree/dev

やってたことは、こんな感じ。

* uvを使った環境にする。
* ``uv run ~~`` で動作しなかったエラーを、Claude Codeに修正させる。
* Linux系向けに、Taskfileでタスクを整理する。
* ビルドできたフォントをWindows側にインストールして、無事に問題がクリアしたっぽいことを確認する。

HackGenと違って、UDEV GothicはPythonのバージョンを問わなそうな説明になっており、
実際にPyrhon 3.14で(多少の修正をすれば)特に問題なかったので、割と楽に対応できた印象がある。

ちょっと見え方に変化が起きてしまってはいるものの、変なストレスもないので当分はこっちを使おうと思っている。
